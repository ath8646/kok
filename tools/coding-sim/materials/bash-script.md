[리눅스 시스템 프로그래밍] 9주차 강의 정리 - 쉘 스크립트 기초

1. 쉘 스크립트란?
쉘 스크립트는 명령어를 순서대로 적어 둔 텍스트 파일이다. 터미널에 한 줄씩 치던 명령을 파일 하나에 모아 두면 같은 작업을 언제든 다시 실행할 수 있다. 첫 줄에는 보통 #!/bin/bash 를 적어서 이 파일을 bash 로 해석하라고 알려 준다. 이 줄을 셔뱅(shebang)이라고 부른다.

```bash
#!/bin/bash
# run.sh - 첫 번째 스크립트
name="KOK"
echo "Hello, $name"
echo "홈 디렉터리: $HOME"
```

파일을 만들었다고 바로 ./run.sh 로 실행되지는 않는다. 실행 권한이 없으면 Permission denied 오류가 뜬다. chmod +x run.sh 로 실행 권한을 주면 ./run.sh 로 실행할 수 있다. 권한이 없어도 bash run.sh 라고 쓰면 실행은 된다. 시험에 자주 나온다: ./run.sh 와 bash run.sh 의 차이, 그리고 실행 권한이 없을 때 생기는 오류.

2. 변수 다루기
변수는 이름=값 형식으로 만든다. 등호 양옆에 공백을 두면 안 된다. `x=10` 은 맞지만 `x = 10` 은 명령 x 를 찾으라는 뜻이 되어 오류가 난다. 값을 읽을 때는 이름 앞에 $ 를 붙인다. 뒤에 다른 글자가 붙어야 하면 ${name}_백업 처럼 중괄호로 감싼다.

작은따옴표 'a' 안에서는 $ 가 펼쳐지지 않고 글자 그대로 나온다. 큰따옴표 "..." 안에서는 $ 가 값으로 바뀐다. 그래서 echo "$HOME" 은 집 경로를 출력하고, echo '$HOME' 은 $HOME 이라는 글자를 그대로 출력한다. 시험에 자주 나온다: 두 따옴표의 차이.

명령의 결과를 변수에 담을 때는 $(명령) 을 쓴다. $(date) 는 현재 날짜와 시간을 만들고, today=$(date +%Y-%m-%d) 라고 쓰면 today 에 오늘 날짜가 들어간다. 옛 방식인 역따옴표 치환도 있지만 요즘 시험에서는 $(...) 형식이 더 자주 나온다.

산술 계산은 $((식)) 으로 한다. a=3, b=4 일 때 sum=$((a + b)) 이면 sum 은 7이 된다. 쉘 변수는 기본적으로 글자로 저장되므로 계산이 필요하면 이 형식을 써야 한다. 카운터를 1 늘리는 식은 i=$((i + 1)) 이다.

3. 위치 매개변수: $0, $1, $#, $@, $?
스크립트 뒤에 붙여 준 인자는 $1, $2 처럼 번호로 읽는다. $0 은 스크립트 이름이고, $# 는 인자가 몇 개인지 알려 준다. 10번째 인자부터는 ${10} 처럼 중괄호를 붙여야 한다. $10 이라고 쓰면 $1 뒤에 글자 0이 붙은 것으로 읽힌다.

$? 는 바로 직전 명령의 종료 상태다. 성공하면 0, 실패하면 0이 아닌 값이 들어간다. 그래서 $? 를 확인하면 앞 명령이 잘 끝났는지 알 수 있다.

```bash
#!/bin/bash
# 사용법: ./check.sh 파일1 파일2 ...
echo "스크립트 이름: $0"
echo "인자 개수: $#"
echo "첫 번째 인자: $1"

for item in "$@"; do
    echo "- $item"
done

ls /nonexistent 2>/dev/null
echo "직전 명령 종료 상태: $?"
```

시험에 자주 나온다: "$@" 와 "$*" 의 차이. 큰따옴표로 감싸면 "$@" 는 인자 하나하나가 따로 유지되고, "$*" 는 모든 인자가 하나의 문자열로 합쳐진다. shift 명령은 인자를 한 칸씩 앞으로 민다. shift 를 한 번 하면 $2 가 $1 자리로 오고 $# 는 1 줄어든다.

4. 조건문: if [ ... ]
조건은 대괄호 [ 와 ] 안에 쓴다. 대괄호 바로 안쪽에는 공백이 있어야 한다. 숫자 비교는 -eq(같다), -ne(다르다), -gt(크다), -ge(크거나 같다), -lt(작다), -le(작거나 같다)를 쓴다. 글자를 비교할 때는 = 와 != 를 쓴다. 파일 검사는 -e(존재), -f(일반 파일), -d(디렉터리), -x(실행 가능)가 있다.

if [ "$x" -gt 10 ]; then 은 x 가 10보다 큰지 확인하는 줄이다. 전체 모양은 아래와 같다.

```bash
#!/bin/bash
x=$1
if [ "$x" -gt 10 ]; then
    echo "$x 는 10보다 큽니다"
elif [ "$x" -eq 10 ]; then
    echo "$x 는 10입니다"
else
    echo "$x 는 10보다 작습니다"
fi
```

시험에 자주 나온다: 변수를 큰따옴표로 감싸지 않은 [ $x -gt 10 ] 은 x 가 빈 값일 때 `unary operator expected` 오류가 난다. 그래서 항상 "$x" 로 감싸는 습관을 들인다. 대괄호 대신 [[ ]] 를 쓰면 bash 전용 기능을 쓸 수 있고 단어 나눔 문제도 줄어든다.

5. 반복문: for 와 while
for f in *.txt; do ... done 은 현재 디렉터리의 .txt 파일을 하나씩 f 에 넣어 반복한다. *.txt 는 쉘이 실제 파일 이름 목록으로 펼치는데, 이를 파일 이름 확장(globbing)이라고 한다. 일치하는 파일이 하나도 없으면 *.txt 라는 글자 그대로 한 번 실행되므로 주의한다.

파일 개수를 세는 코드는 다음과 같다. 네 칸 들여쓰기만 하고 울타리는 없다.

    count=0
    for f in *.txt; do
        count=$((count + 1))
    done
    echo "txt 파일은 $count 개입니다"

while 문은 조건이 참인 동안 반복한다. while [ "$i" -lt 5 ]; do 처럼 쓰고, 안에서 i 를 늘린다. 시험에 자주 나온다: done 이나 fi 같은 끝맺음 키워드를 빠뜨리는 실수.

6. 함수
함수는 이름() { ... } 형식으로 만든다. 호출할 때는 괄호 없이 이름과 인자만 쓴다. 함수 안의 $1 과 $# 는 함수가 받은 인자를 가리키므로 스크립트 인자와 구분해야 한다. return 은 종료 상태(0~255)만 돌려주므로, 문자열 값을 돌려주려면 echo 로 출력하고 $(함수이름) 으로 받는다. 시험에 자주 나온다: return 으로 문자열을 돌려주려는 잘못된 답.

7. 명령 연결과 종료
명령1 && 명령2 는 명령1 이 성공했을 때만 명령2 를 실행한다. 명령1 || 명령2 는 명령1 이 실패했을 때만 명령2 를 실행한다. 예를 들어 mkdir backup && cp a.txt backup/ 는 폴더가 만들어진 뒤에만 복사한다. 스크립트를 실패로 끝내고 싶으면 exit 1 을 쓰고, exit 0 은 정상 종료다.

※ 시험 포인트: #!/bin/bash 의 역할과 chmod +x 권한, 변수 대입의 공백 오류, 작은따옴표와 큰따옴표의 차이, $? 의 의미(0 = 성공), [ ] 안의 공백과 -gt 같은 비교 연산자, "$@" 와 "$*" 의 차이, for 에서 *.txt 가 펼쳐지는 과정.
