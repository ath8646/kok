# 운영체제 5주차 강의 정리: 프로세스·스레드·동기화

## 1. 프로세스와 스레드

- 프로세스: 실행 중인 프로그램 한 개. 각자 독립된 주소 공간을 가진다.
- 스레드: 한 프로세스 안의 실행 흐름. 코드, 전역 변수, 힙은 같이 쓰고 스택만 따로 가진다.
- 프로세스를 새로 만드는 비용이 스레드를 만드는 비용보다 훨씬 크다.

운영체제는 프로세스마다 PCB(프로세스 제어 블록)를 두고 상태, PID, 레지스터 값을 기록한다. 문맥 교환이 일어나면 현재 정보를 PCB에 저장하고 다음 프로세스의 정보를 읽어 온다.

실행 중인 프로세스 목록은 ps 명령으로 본다. 각 줄에 PID(프로세스 번호)와 PPID(부모 번호)가 나온다.

## 2. fork와 exec

`fork()`는 호출한 프로세스를 그대로 복제한다. 부모에게는 자식의 PID가, 자식에게는 0이 돌아온다. 그래서 반환값으로 두 쪽이 할 일을 나눈다.

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        execlp("ls", "ls", "-l", NULL);
        perror("execlp");
        return 1;
    }
    wait(NULL);
    printf("자식 종료\n");
    return 0;
}
```

`if (pid == 0) { ... }` 블록은 자식만 실행한다. execlp가 성공하면 그 뒤 코드는 실행되지 않는다. 부모는 wait(NULL)로 자식이 끝날 때까지 기다려야 한다. 자식이 먼저 끝났는데 부모가 wait를 하지 않으면 자식은 좀비 프로세스로 남는다. 반대로 부모가 먼저 끝나면 자식은 고아 프로세스가 되어 시스템 프로세스가 맡는다.

## 3. 스레드 만들기

스레드는 pthread_create로 만든다. 인자는 차례로 스레드 핸들, 속성, 시작 함수, 함수 인자다. 끝날 때까지 기다리는 것은 pthread_join이다.

    pthread_t t;
    pthread_create(&t, NULL, worker, NULL);
    pthread_join(t, NULL);

## 4. 경쟁 조건과 세마포어

두 스레드가 count++를 동시에 하면 결과가 틀릴 수 있다. count++는 읽고, 더하고, 쓰는 세 단계라서 중간에 다른 스레드가 끼어들기 때문이다. 이런 상황을 경쟁 조건(race condition)이라고 한다. 두 스레드가 각각 100000번씩 더하면 정답은 200000이어야 한다.

세마포어 s를 1로 두고 임계 구역을 감싸면 한 번에 한 스레드만 들어간다.

```c
sem_t s;
int count = 0;

void *worker(void *arg) {
    for (int i = 0; i < 100000; i++) {
        sem_wait(&s); count++; sem_post(&s);
    }
    return NULL;
}
```

초기화는 sem_init(&s, 0, 1)로 한다. sem_wait는 값이 0이면 기다리고, 0보다 크면 값을 1 줄이고 들어간다. sem_post는 값을 1 늘리고 기다리던 스레드를 깨운다.

## 5. 셸에서 확인하기

    $ ./a.out &
    $ ps -ef | grep a.out
    $ echo $?

직전 명령의 종료 상태는 echo $?로 본다. 0이면 정상 종료다.

## 시험 포인트

- fork 반환값: 부모는 자식 PID, 자식은 0, 실패는 -1.
- exec 계열 함수가 성공하면 원래 코드로 돌아오지 않는다.
- wait를 빼먹으면 좀비 프로세스가 생긴다.
- 스레드는 전역 변수를 공유하므로 동기화가 필요하다.
