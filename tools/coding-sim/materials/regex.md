[텍스트 처리와 언어] 7주차 강의 정리 - 정규 표현식

1. 정규 표현식이란?
정규 표현식(regular expression, 줄여서 regex)은 문자열이 어떤 모양인지 짧은 규칙으로 적은 것이다. 전화번호처럼 "숫자 세 개, 하이픈, 숫자 네 개" 같은 모양을 찾거나 검사할 때 쓴다. 대부분의 언어가 문법을 거의 같이 쓰지만 세부 규칙은 조금씩 달라서, 시험에서는 어느 언어 기준인지 함께 묻는 경우가 많다.

2. 메타 문자 정리
아래 기호들은 글자 그대로가 아니라 특별한 뜻을 가진다. 기호 자체를 찾고 싶으면 앞에 역슬래시(\)를 붙인다.

. : 줄바꿈을 뺀 글자 한 개와 맞는다
^ : 문자열(또는 줄)의 맨 앞. 글자가 아니라 위치다
$ : 문자열(또는 줄)의 맨 끝. 글자가 아니라 위치다
* : 앞의 것이 0번 이상 반복
+ : 앞의 것이 1번 이상 반복
? : 앞의 것이 0번 또는 1번 (있어도 되고 없어도 됨)
{m,n} : 앞의 것이 m번 이상 n번 이하. {4} 만 쓰면 정확히 4번
[ ] : 안에 든 글자 중 한 개. [0-9] 는 숫자 한 개
( ) : 묶음(그룹). 묶은 부분을 나중에 따로 꺼낼 수 있다
| : 또는. a|b 는 a 나 b
\d : 숫자 한 개. [0-9] 와 보통 같다
\w : 영문자, 숫자, 밑줄(_) 중 한 개
\s : 빈칸, 탭, 줄바꿈 같은 공백 한 개

3. 자주 나오는 패턴 읽기
시험에서는 패턴을 보고 "무엇과 맞는가"를 묻는다. 한 조각씩 나눠 읽으면 쉽다.

^\d{3}-\d{4}$ 는 숫자 3개, 하이픈, 숫자 4개이고 앞뒤에 다른 글자가 없어야 한다. 그래서 010-1234 는 맞고 a010-1234 는 틀리다.

`[A-Za-z_]\w*` 는 프로그래밍 언어의 변수 이름 모양이다. 첫 글자는 영문자나 밑줄이고, 그 뒤에는 영문자, 숫자, 밑줄이 0번 이상 온다. 그래서 1abc 는 맞지 않는다.

`(?<=\$)\d+` 는 달러 기호 바로 뒤에 오는 숫자를 찾는다. `(?<=...)` 은 뒤쪽 확인(lookbehind)이라고 부르며, 그 안의 글자는 결과에 들어가지 않는다. $1500 에서 잡히는 것은 1500 뿐이다.

4. Python re 모듈
`re.search(패턴, 문자열)` 은 문자열 어디에서든 처음 맞는 곳을 찾는다. re.match 는 문자열의 맨 앞에서부터 맞아야 하고, re.fullmatch 는 문자열 전체가 맞아야 한다. 세 함수의 차이는 시험에 거의 매번 나온다.

```python
import re

phone = r"^\d{3}-\d{4}$"
print(re.fullmatch(phone, "010-1234"))   # 맞음, 객체가 나온다
print(re.fullmatch(phone, "0101234"))    # None, 하이픈이 없다

m = re.search(r"(?<=\$)\d+", "가격은 $1500 입니다")
print(m.group())                         # 1500
```

패턴 앞의 `r` 은 raw 문자열이라는 뜻이다. r 을 빼면 역슬래시가 이스케이프 문자로 먼저 해석될 수 있어서 "\\d" 처럼 두 번 써야 한다. 이 차이도 시험에 자주 나온다.

괄호로 묶은 부분은 group(번호)로 꺼낸다. 번호는 여는 괄호의 순서대로 1번부터 붙는다.

    text = "2026-10-31"
    m = re.fullmatch(r"(\d{4})-(\d{2})-(\d{2})", text)
    print(m.group(1))    # 2026
    print(m.group(3))    # 31

5. JavaScript 에서는
JavaScript 에서는 정규 표현식을 `/패턴/플래그` 형태로 쓴다. 플래그 `g` 는 여러 번 찾기, `i` 는 대소문자 무시, `m` 은 ^ 와 $ 를 줄마다 적용한다. 이름 붙은 묶음은 Python 에서는 (?P<이름>...) 으로, JavaScript 에서는 (?<이름>...) 으로 쓴다.

```javascript
const price = "가격은 $1500 입니다";
const found = price.match(/(?<=\$)\d+/);
console.log(found[0]);                     // "1500"

const name = "user_01";
console.log(/^[A-Za-z_]\w*$/.test(name));  // true
```

6. 탐욕(greedy)과 게으름(lazy)
* 나 + 는 기본적으로 가능한 한 길게 맞춘다. 이것을 탐욕(greedy) 방식이라고 한다. `<.*>` 는 "<a><b>" 전체와 맞는다. 짧게 맞추고 싶으면 `?` 를 뒤에 붙여 `<.*?>` 로 쓰고, 그러면 "<a>" 만 맞는다. 이것이 게으름(lazy) 방식이다. 같은 문자열에서 결과가 어떻게 달라지는지 묻는 문제가 자주 나온다.

7. 시험 포인트
※ 시험에 자주 나온다: `[^abc]` 처럼 대괄호 맨 앞의 ^ 는 "이 글자들이 아닌 것"이라는 뜻이다. 대괄호 밖의 ^ 는 문자열의 맨 앞이라는 뜻이라 헷갈리기 쉽다.
※ 시험에 자주 나온다: 점(.)은 줄바꿈을 맞추지 않는다. 달러 기호 자체를 찾을 때는 \$ 라고 쓴다.
※ {3,} 는 세 번 이상, {3} 은 정확히 세 번이다. 쉼표의 위치가 뜻을 바꾼다.
※ \d 는 보통 [0-9] 와 같지만, 언어와 옵션에 따라 더 많은 글자를 맞출 수 있다. Python 3 의 str 패턴이 그런 예다.
※ 이론 수업에서는 정규 언어만으로는 괄호 짝 맞추기처럼 중첩된 구조를 검사할 수 없다고 배운다. 그래서 HTML 같은 중첩 구조를 정규 표현식으로 파싱하면 안 된다고 한다.
