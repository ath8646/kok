[시스템프로그래밍] 5주차 강의자료 - 셸 명령과 Git 브랜치

오늘은 리눅스 셸에서 자주 쓰는 명령어와, 팀으로 작업할 때 쓰는 Git 브랜치의 기본 흐름을 배웠다. 교수님이 "직접 쳐 보고 결과를 눈으로 확인하라"고 여러 번 말씀하셨다. 실습 파일은 강의 사이트에 올라와 있다.

1. 환경 변수와 PATH

셸에는 이름과 값을 가진 변수가 있다. 값을 읽을 때는 이름 앞에 $ 를 붙인다. 내 홈 디렉터리 경로는 `echo $HOME` 으로 확인하는데, 출력이 /home/student 처럼 나오면 된다.

PATH 는 명령어를 찾아갈 폴더들의 목록이다. 폴더 경로는 콜론(:)으로 이어 적는다. 새 프로그램이 들어 있는 폴더를 추가하려면 export 를 쓴다.

```bash
echo $HOME
export PATH=$PATH:/usr/local/bin
echo $PATH
```

export 로 바꾼 값은 지금 열려 있는 셸에서만 유지된다. 터미널을 새로 열면 사라지니, 계속 쓰려면 ~/.bashrc 파일에 적어야 한다. 시험에 나온다고 하셨다.

which 명령으로 어떤 프로그램이 실행될지 찾을 수 있다. which python3 을 치면 python3 의 위치가 나온다. 같은 이름의 프로그램이 여러 폴더에 있으면 PATH 에서 앞에 있는 폴더의 것이 먼저 실행된다는 점이 중요하다고 강조하셨다.

2. 파이프와 필터

명령의 출력을 다른 명령의 입력으로 넘길 때 파이프 | 를 쓴다. 왼쪽 명령의 결과가 오른쪽 명령으로 흘러간다. grep 은 입력받은 줄 가운데 원하는 글자가 들어 있는 줄만 골라 준다. ls 의 -a 는 숨김 파일까지, -l 은 권한과 크기를 자세히 보여 준다.

    ls -al | grep "*.py"

실습 때 이 명령을 치니 아무것도 나오지 않았다. 따옴표 안의 * 는 셸이 파일 이름 패턴으로 바꾸지 않고, grep 이 "*" 라는 글자 자체를 찾기 때문이다. 파일 이름으로 거르고 싶으면 따옴표 없이 ls *.py 라고 쓰면 된다.

파이프는 여러 개를 이어 쓸 수도 있다. 명령 두 개를 이으면 셸이 두 프로그램을 동시에 돌리면서 데이터만 넘겨준다는 점을 기억하자.

3. 권한과 실행

파일 권한은 소유자, 그룹, 기타 사용자 세 묶음으로 나뉜다. 각 묶음은 읽기 r(4), 쓰기 w(2), 실행 x(1)의 합으로 숫자를 만든다.

    chmod 755 run.sh
    ./run.sh 2>&1 | tee log.txt

7 은 4+2+1 이라 rwx, 5 는 4+1 이라 r-x 이다. 그래서 755 는 소유자는 모든 권한, 나머지는 읽기와 실행만 가능하다는 뜻이다. 실행 파일이 PATH 에 없는 현재 폴더의 파일이면 ./ 를 앞에 붙여야 한다.

같은 권한을 기호로도 쓸 수 있다. chmod u+x run.sh 는 소유자에게 실행 권한만 더한다는 뜻이다. 숫자 방식과 기호 방식 가운데 골라 쓰면 되는데, 시험에서는 숫자로 쓰는 문제가 더 많이 나온다고 하셨다.

2>&1 은 표준 에러(2)를 표준 출력(1)이 가는 곳으로 보내라는 뜻이다. tee 는 받은 내용을 화면에 보여 주면서 동시에 파일에도 쓴다. 그래서 실행 로그가 log.txt 에 남는다.

4. Git 브랜치와 커밋

프로젝트 폴더로 가서 빌드까지 한 줄로 하려면 && 를 쓴다. 앞 명령이 성공해야 뒤 명령이 실행된다.

```bash
cd ~/project && make
git checkout -b feature/login
git commit -m "fix: 로그인 오류"
git log --oneline
```

git checkout -b 는 새 브랜치를 만들고 바로 그 브랜치로 옮겨 간다. 최신 Git 에서는 git switch -c 와 같은 일을 한다. git commit -m 뒤의 따옴표 안이 커밋 메시지이고, git log --oneline 은 커밋 기록을 한 줄씩 보여 준다. 메시지 앞의 fix: 는 버그를 고쳤다는 뜻의 관례라고 하셨다.

브랜치를 나누는 이유는 main 에 바로 올리지 않고 기능마다 따로 작업하기 위해서다. git branch 를 치면 브랜치 목록이 나오고, 지금 있는 브랜치 앞에는 * 표시가 붙는다. 커밋하기 전에는 git status 로 어떤 파일이 바뀌었는지 확인하는 습관을 들이라고 하셨다. 작업이 끝나면 git push -u origin feature/login 으로 원격 저장소에 올린다.

과제: run.sh 의 권한을 755 로 바꾸고, 실행 로그를 log.txt 로 남겨서 깃허브 저장소에 올릴 것. 마감은 다음 주 월요일 자정.
